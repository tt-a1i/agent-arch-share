四个特征出自 DeepSeek 原文；「管家」是我们的比喻
把 agent 从「人手动驱动的单会话」里解耦出来，变成一个持续存在的实体。 四个特征（DeepSeek 原文）：Continuous 跨渠道连续（IM、GitHub 上是同一个它）；Productive 并行干活（随时接新指令）；Proactive 主动但克制（监听环境事件，值得做才做）；Persistent 常驻不掉线（一直在线，崩了能自己恢复）。 不是新理论：原文说，它把计算机系统的经典思想（事件驱动、批处理、缓存、看门狗）搬到 agent 上。 ChatGPT dots 的产品叙事几乎一致：「把更多时间和注意力拿回来」。

Thread = 同一件事的一串消息：一个 IM 话题 / 回复串、一个 PR、一封邮件链。 第一条事件 → 路由开任务会话，会话订阅这个 Thread；之后这个 Thread 的消息 → 代码直送给订阅的会话；Router 看得到，但不用判断和转发。 不带话题 / 回复、直接发的新消息 → 自成新 Thread → 交给路由判断；只有明确指向某个任务才挂上（原型：「话题相似不够」）。挂错了，会话可以把它交还路由。 原文消融：去掉直送，cache-read token 多约 37%（23.2M → 31.8M），Router 决策多约 30%；完成时间几乎一样 —— 直送不会让任务更快、更好，只省路由的 token。合成负载，每轮约 300 条消息（约 20 条工作请求），每种设计跑 5 次。 前面还有两段过滤：先代码规则（来源、群、白名单），再 LLM 语义判断 —— 能用代码判断的，不交给模型。 对应到我们：大内总管 ≈ 路由；Thread 是你和 bot 聊的「某一串话」，不是某个 bot。

11路由的模型第三幕 · 我们的思考12 / 18

路由用多强的模型？
看你留给它多少判断空间。

01 · 默认轻量模型大部分消息，分派并不难
02 · 拿不准升级强模型低置信 · 对外或不可逆 · 要合并多个结果
03 · 还拿不准问人一次只问一个具体问题

压缩判断空间：代码规则过滤 · 订阅直送 · 结构化结果

升级机制是我们的设计建议，原文未描述（原文把「为 Router 专门训练模型」列为开放问题）互动：拖动消息频率
弱模型的三个坑：① 意图模糊时拆错派错：「那个 PR 顺便也看看文档」是一件还是两件？② 该不该打扰你：本身就是高判断量决策。③ 转述漏前提：「X 成立时 Y 可合并」→「Y 可合并」。 「不计成本就上最强」—— 只算了钱，没算时间。路由在每条消息的必经路径上：下层慢你感觉不到，路由慢你每句话都要等。 原文压测：批处理把摊到每个决策的推理时间从 6.4s 降到 1.6s，但单次请求 2.5s → 3.9s。 结构化结果：结论 / 前提 / 待你决定。升级机制是我们的设计建议，原文未描述。
