# 第八节 §8.3：从 Super-agent 到组织级协作

> 讨论推演和假设；不是 DeepSeek 已落地的组织产品设计。

## 为什么比单纯 A2A 协议更复杂

一个 Agent 服务个人，多个 Agent 进入组织时，首先遇到的是：信息不完整、不同人具有不同权限与目标、真实决定可能存在于私聊和未记录背景中。传统企业软件面向人类工作习惯，消息数字化并不保证组织承诺、依赖、决定可被机器可靠理解。

## 四种不同的边界

1. **知识边界**：谁能读取、持久保存或共享什么。
2. **执行边界**：谁能调用哪些工具、操作什么环境。
3. **决策边界**：谁可以作出承诺、调整优先级、批准发布。
4. **责任边界**：发生问题时谁承担复核、接管与问责。

“共享项目文档”不等于“共享 Agent 实例”，更不等于“共享决定权”。

## 现实信息瓶颈

此前已有通过 IM 群聊、会议纪要、项目文档分析项目进度/风险的实践。主要问题首先是信息拿不到：项目调整可能发生于私聊、线下或个人工具；其次是即使取到了信息，候选事实、正式决定、未确认假设仍需区分。

正在探索的个人工作记录方案包括：macOS Accessibility Tree 获取界面内容、无法获取时截图、输入框信息及 Agent Session 分析，形成个人日常工作线索。这是**工作活动观察**，不能直接证明任务完成，更不应默认将个人原始数据集中到组织服务器。

## 一个可验证的渐进路线

个人侧授权观察 → 生成候选任务事件 → 通过 PR/CI/文档或本人确认核验 → 进入项目共享状态 → 在权限边界内发起 Agent 间协作 → 人处理重大授权或目标冲突。

需验证：项目状态更新时效、错误归因、员工接受度、隐私风险、人工汇报减少量和总运行成本。

## 不预设最终拓扑

可探索组织级中心 Agent、个人 Agent 直接协作、共享状态系统、分层混合组织。比较具体工作负载下的信息完整度、任务依赖和冲突密度，不将未来组织结构等同于当前部门层级。
